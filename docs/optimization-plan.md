# 周计划（weeklyTodo）优化方向清单

> 目标：以冲刺 1.0 正式发布为主（P0），兼顾个人日常使用体验（P1/P2）。
> 红线：严守「本地优先」，不引入服务端 / 账号体系，同步只走现有 WebDAV。
> 依据：逐项核对 `src/`（React 19）与 `src-tauri/`（Tauri 2 + rusqlite）代码实况，
> 区分「已实现但可增强」与「完全缺失」两类。
> 版本基线：package.json 0.9.8 / Cargo.toml 0.9.9 / tauri.conf.json 0.9.9（存在漂移，见 R1）。

## 分级定义

- **P0**：1.0 发布门槛。缺了会影响正式版完整度、数据安全或存在明确缺陷/误导。
- **P1**：值得尽快做。明显提升日常使用效率或补齐核心场景，工作量可控。
- **P2**：锦上添花。体验增强，可延后或按需挑选。

## P0 · 1.0 发布门槛

### F1 【功能】任务增加「已取消 / 归档」状态（与带入机制配套）

- **现状**：任务只有 `in_progress` / `closed` 两态（`domain.rs`、`types.ts`）。上周未完成任务无条件带入本周。
- **问题**：用户无法对"这周不想再做的任务"说"放弃"，只能完成或让它在每周带入里永远存在，导致任务树不断积累无意义分支。
- **建议**：新增 `cancelled` 状态；带入逻辑跳过已取消任务；树中显示为弱化样式，可在历史查询中检索。`closed` 保留为"完成"。
- **成本**：中。涉及 `domain.rs`（状态常量、带入过滤、close/reopen 命令）、`types.ts`、`TaskDetailPanel`、`CurrentActions`（叶子过滤）、查询面板状态筛选。
- **风险**：低。纯增量字段，无迁移压力（沿用现有 status TEXT）。

### F2 【功能】数据导出 / 手动备份（本地优先的底线）

- **现状**：数据只有单文件 SQLite。备份仅出现在两类路径：WebDAV 同步（可选功能）和存储迁移（自动 `.pre-migration.bak`）。
- **问题**：未启用 WebDAV 的用户没有任何备份出口；误删/磁盘故障即全部丢失。
- **建议**：设置「存储」页增加：
  1. 「导出数据库副本」（复制 `weeklytodo.db`，含 WAL checkpoint）；
  2. 「导出全部数据为 JSON / Markdown」（跨周导出，便于归档与迁移）。
- **成本**：低-中。Rust 侧新增导出命令（checkpoint 后复制 + 序列化），前端加按钮与保存对话框（复用现有 dialog 插件）。
- **风险**：低。

### I1 【交互】「查询全部」的 `Ctrl K` 提示未实现

- **现状**：`WeekRail.tsx` 按钮上渲染 `<kbd>Ctrl K</kbd>` 提示；全代码库无任何 Ctrl+K 键盘监听。
- **问题**：有提示无功能，1.0 前必须修。
- **建议**：实现全局 `Ctrl/Cmd+K` 打开查询面板（推荐，符合直觉）；或移除 `<kbd>` 提示。
- **成本**：低。全局 keydown 监听 + 打开 `QueryView`。
- **风险**：低。

### R1 【发布/UI】版本号三处漂移：package.json 0.9.8 vs Rust 侧 0.9.9

- **现状**：`package.json=0.9.8`，`Cargo.toml / Cargo.lock / tauri.conf.json=0.9.9`。顶栏 `v{__APP_VERSION__}` 读 package.json 显示 0.9.8；更新检查用 `CARGO_PKG_VERSION`（0.9.9）。上一次 `chore(release): bump version to 0.9.9` 未同步 package.json。
- **问题**：用户看到的版本与实际不符；下次发版若继续只 bump 一侧，可能造成"永远提示有新版本"或"顶栏版本倒退"。
- **建议**：统一版本来源（如 `__APP_VERSION__` 改由 Rust 侧返回，或 release 时强制四文件同步并加 CI 校验）。可将「release-version」技能流程固化为脚本 + CI 断言。
- **成本**：低。
- **风险**：低。

## P1 · 值得尽快做

### F3 【功能】快速添加任务（托盘菜单 / 全局快捷键）

- **现状**：托盘仅有「显示主界面 / 退出」；应用常驻后台（关闭行为支持最小化到托盘）。
- **问题**：随时记下一个任务，必须先唤起主窗口 → 点新建 → 输入，路径长。
- **建议**：托盘菜单加「快速添加任务」，弹出迷你输入框（Tauri 新建小窗口或复用主窗口 modal）；可选全局快捷键（如 `Ctrl+Alt+T`）。
- **成本**：中。涉及 `tray.rs`（菜单项 + 事件）、新前端小窗口或 modal、`create_task` 命令复用。
- **风险**：低-中。全局快捷键需注意与系统其他应用冲突。

### F4 【功能】任务计划日期 + 当前行动按日期分组

- **现状**：任务无任何日期属性（除 created/updated/closed）；「当前行动」只按树结构列出全部叶子。
- **问题**：周计划的核心是"这一周哪天做什么"，目前完全靠用户脑补；叶子一多，面板就退化为长列表。
- **建议**：
  1. 任务增加可选「计划日期」（周内某天）与「截止日期」；
  2. 「当前行动」面板按日期分组（今天 / 本周剩余 / 无日期），支持按 P0 优先排序。
- **成本**：中-高。涉及 schema 迁移（DB 加列，SCHEMA_VERSION 4）、`domain.rs`、`types.ts`、`TaskDetailPanel`、`CurrentActions`。
- **风险**：中。数据模型变更需迁移与 WebDAV 同步兼容性验证（旧库自动加列，注意文件级同步的整库覆盖不冲突）。

### F5 【功能】数据导入（JSON / CSV）

- **现状**：只读导出方向无导入。
- **问题**：从其他工具（TickTick、微信收藏、Excel 周计划表）迁移进入成本高，影响从 0 到 1 的用户获取。
- **建议**：支持导入 F2 导出的 JSON（含父-子结构与周）以及简单 CSV（标题/优先级/标签）。
- **成本**：中。
- **风险**：中。需校验数据合法性、处理重复周与 id 冲突。

### F6 【功能】历史统计 / 复盘视图

- **现状**：仅顶部周进度条（完成率）与查询面板的周完成数。
- **问题**：周计划工具的价值闭环在「周回顾」；当前没有连续趋势、按标签/负责人/优先级分布。
- **建议**：只读「统计」视图（复用现有 `week_summaries` 数据 + 少量聚合查询）：近 N 周完成率趋势、带入 vs 新增比例、按标签/负责人分布。
- **成本**：中。
- **风险**：低。纯新增查询 + 前端视图。

### I2 【交互】键盘导航与快捷键体系

- **现状**：除新建输入框 Enter/Esc、查询面板 Esc 外，主界面无键盘支持。
- **问题**：个人高频工具，纯鼠标拖拽/点击在数据量变大后效率低。
- **建议**：任务树支持 ↑/↓ 导航、Enter 编辑、Space 切换完成、Tab/Shift+Tab 缩进/提升；快捷键：`Ctrl+K` 查询、`Ctrl+N` 新建、`Ctrl+F` 过滤。
- **成本**：中。
- **风险**：低-中。注意与输入框内按键冲突。

### I3 【交互】删除撤销（软删除 + 撤销提示）

- **现状**：`delete_task` 级联删除整个子树（`ON DELETE CASCADE`），UI 仅 4 秒二次确认，无撤销。
- **问题**：误删不可恢复；4 秒防误触窗口对高价值数据不够稳。
- **建议**：删除改为软删除（`deleted_at` 列）或引入「最近删除」抽屉；删除后 toast「已删除，可撤销」，10 秒内可恢复；仍保留二次确认。
- **成本**：中-高。涉及 schema、`domain.rs`、`delete_task` 命令与前端状态。
- **风险**：中。软删除需全链路过滤（查询/带入/统计），回归面较大，建议配合测试。

### U1 【UI】深色模式（跟随系统 + 手动切换）

- **现状**：`ConfigProvider` 固定 `theme.defaultAlgorithm`（亮色），`styles.css` 的 `:root` 变量也是亮色系。
- **问题**：Windows 用户大量使用深色主题，桌面应用不跟随系统主题在观感上明显落后。
- **建议**：用 `window.matchMedia('(prefers-color-scheme: dark)')` 跟随系统 + 设置手动覆盖；把 `:root` 变量整理为 `[data-theme]` 两套主题（变量体系已存在，改造可控）。
- **成本**：中-高（需全局过一遍所有硬编码颜色，含 Ant Design token 联动）。
- **风险**：中。UI 回归面大，建议渐进式：先落地变量切换，再逐组件校验。

### S1 【安全】CSP 未配置

- **现状**：`tauri.conf.json` 中 `"csp": null`。
- **问题**：Tauri 官方推荐显式 CSP；虽然应用不加载远程内容，配置 CSP 可显著降低未来引入外部资源（如描述里的远程图片/链接）时的注入风险。
- **建议**：按 Tauri 文档配置 `default-src 'self'` + 必要放宽（`connect-src` 覆盖 GitHub 更新与 WebDAV 域名），并保留非 `null` 值。
- **成本**：低。
- **风险**：低-中。需在发布前实测更新下载、WebDAV 同步不受影响。

### F7 【功能/交互】首次运行数据目录引导（与 README 不符）

- **现状**：README 声称「首次运行选择数据目录」；实际 `ensure_storage` 自动选目录（exe 旁可写的 `data/` 否则 APPDATA），无任何引导界面。
- **问题**：对「本地优先、数据位置敏感」的应用，用户不知道自己数据存哪；后续想换目录只能去设置页手动迁移。
- **建议**：首次启动展示引导页（说明数据存本机 → 显示/选择目录 → 开始使用），或至少在首屏提示数据目录位置。并同步修正 README。
- **成本**：中（引导页需处理初始化流程时序）。
- **风险**：低-中。

## P2 · 锦上添花

### F8 【功能】周期性任务模板

- **现状**：未完成任务每周自动带入已近似"重复"，但没有"每周固定任务（如周报）自动预建"。
- **建议**：为任务标记「每周自动创建」，新周创建时自动预建（不占带入额度）。
- **成本**：中。

### F9 【功能】描述支持 Markdown / 链接渲染

- **现状**：描述为纯文本框，查询面板不渲染内容。
- **建议**：详情面板渲染轻量 Markdown（换行、列表、粗体、链接可点开），需引入安全渲染（避免 CSP/注入问题）。
- **成本**：低-中。

### I4 【交互】拖拽体验增强（ghost 预览 / 触控支持）

- **现状**：HTML5 Drag & Drop，拖拽中无预览 ghost，悬停操作在触屏/笔电上不可用。
- **建议**：自定义拖拽预览 + 触控长按拖拽；或将行内操作改为常显图标（触屏友好）。
- **成本**：中。

### I5 【交互】完成/移动微动效

- **建议**：「当前行动」完成时条目淡出动画、任务勾选过渡、周切换淡入。纯体验增强。
- **成本**：低。

### U2 【UI】About 页增强 + 空状态打磨

- **现状**：About 页只有版本与存储信息；周列表空状态「暂无周数据」较简陋。
- **建议**：About 页加「打开数据目录」按钮（一键定位数据库文件，便于手动备份）；统一各处空状态插画/文案。
- **成本**：低。

### U3 【UI】高 DPI / 缩放适配验证

- **建议**：在 125% / 150% 缩放下过一遍布局（三栏 grid、长任务标题截断、固定宽度 modal），修正溢出。
- **成本**：低。

### F10 【功能】WebDAV 同步冲突提示改进

- **现状**：文件级"后写覆盖"同步，被覆盖方有 `.bak` 备份；但同步结果提示未强调"本地/远端被覆盖"的数据影响。
- **建议**：提示文案更明确（"远端旧版已备份为 xxx，本地数据已覆盖远端"），并在同步失败时给出重试/手动同步入口。
- **成本**：低。

## 建议执行顺序

1. **发布卫生**：R1（统一版本来源）→ I1（Ctrl+K）—— 工作量小、立刻消除缺陷。
2. **数据安全**：F2（导出/备份）→ I3（删除撤销，可与 F1 的 schema 变更合并做一次迁移）。
3. **核心模型**：F1（取消状态，随带入逻辑一起改）→ F4（计划日期 + 当前行动分组）。
4. **效率**：I2（快捷键）→ F3（快速添加）→ F5（导入）。
5. **体验/安全收尾**：U1（深色）→ S1（CSP）→ F7（首启引导）→ F6（统计视图）。
6. **P2 项**按需挑选，不与 1.0 阻塞。

> 注：F1/I3 若同时涉及 schema 变更，建议合并为一个 DB 迁移（SCHEMA_VERSION 4），并同步验证 WebDAV 整库文件同步不受影响。
